## Что такое Session #1 и Session #2

Представь: ты открываешь **два отдельных окна терминала** на одном компьютере. В каждом окне ты подключаешься к **одной и той же базе данных** командой `psql`. Это и есть два сеанса — два независимых подключения к PostgreSQL, которые работают **одновременно**.

Суть эксперимента — ты руками, **поочерёдно**, вводишь команды то в одном окне, то в другом, строго по порядку из задания. Это как два человека сидят за разными компьютерами и одновременно работают с одной БД.

## Что конкретно делать

Шаг за шагом:

1. Открываешь **терминал №1**, подключаешься: `psql -d pizza_db`
2. Открываешь **терминал №2**, подключаешься: `psql -d pizza_db`
3. Вводишь команды **строго по очереди**, переключаясь между окнами по порядку из задания
4. Делаешь **скриншот** каждого окна
5. Пишешь **SQL-файл** с комментариями, какая команда в каком сеансе выполнялась

Порядок из задания Ex00 такой:

```
Окно 1: BEGIN;
Окно 1: UPDATE ...
Окно 1: SELECT ... (видишь rating = 5)
Окно 2: SELECT ... (видишь rating = 4.6 — старое значение!)
Окно 1: COMMIT;
Окно 2: SELECT ... (теперь видишь rating = 5)
```

## Решение с подробными комментариями## Ответы на твои вопросы

**Вносит ли решение непоправимые изменения?** Нет. Рейтинг Pizza Hut после эксперимента станет 5 вместо 4.6. Но блок идемпотентности в самом начале файла (`UPDATE ... SET rating = 4.6`) возвращает значение обратно перед каждым запуском. Так что можно повторять сколько угодно раз.

**Можно ли повторять?** Да. Просто сначала выполни тот самый первый UPDATE (возврат к 4.6) в любом из окон, и запускай эксперимент заново.

**Хронология действий руками** — именно в таком порядке переключаешься между двумя окнами терминала:

| Шаг | Где вводишь | Команда | Что происходит |
|-----|------------|---------|----------------|
| 1 | Окно 1 | `BEGIN;` | Открыли транзакцию |
| 2 | Окно 1 | `UPDATE ... SET rating = 5` | Изменили, но только «для себя» |
| 3 | Окно 1 | `SELECT ...` | Видим rating = 5 |
| 4 | Окно 2 | `SELECT ...` | Видим rating = 4.6 (старое!) |
| 5 | Окно 1 | `COMMIT;` | Опубликовали изменения |
| 6 | Окно 2 | `SELECT ...` | Теперь видим rating = 5 |

Шаг 4 — ключевой момент всего задания. Он доказывает, что **незафиксированные изменения невидимы** другим сеансам. Это и есть свойство **Isolation** (изоляция) из ACID.
